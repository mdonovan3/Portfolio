Working name  ·  concept in development

Make the why a queryable object.

Across historical linguistics, viral genomics, cancer evolution and disease progression, we have good tools for describing what changed and when. The why ends up as a sentence in a discussion section — un‑versioned, un‑queryable, invisible at corpus scale. This is a framework for storing it instead.

Three theories score the same transition at once. The system stores all three posteriors, separately — it never merges them into one answer. “Which theory tracked the documented outcome?” then becomes a query, not an argument.

The problem

Causal attribution has nowhere to live.

A tool produces a phylogenetic tree, a clonal-evolution diagram, a biomarker trajectory. An expert reads it and writes down what they think drove the change. That judgement is the most valuable output in the pipeline — and the only one with no data model.

“The observed divergence is most consistent with immune-evasion pressure, with a possible contribution from founder effects in the founding population.” — discussion section, somewhere on page 11
→
// one row in transition_inferences
{
  "cause_distribution": {
    "immune_evasion":   0.58,
    "transmission_adv": 0.19,
    "founder_effect":   0.15,
    "drift":            0.08
  },
  "confidence":      0.71,
  "grammar_version": "3.1",
  "evidence_atoms":  [ "rbd_substitution", … ],
  "rule_trace":      [ "evasion_via_rbd" ]
}

Once the judgement is a row, the things a researcher actually wants become ordinary operations. Update it when a follow-up sample arrives. Compare it against a colleague's competing theory. Re-score it when the theory is revised, and keep the old score. Rank a hundred thousand transitions by where the current theory is under the most strain. None of that is possible with a paragraph.

The objects

Three record types, none of them derived.

The framework is domain-agnostic. The three objects apply to any system where structured state changes over time and the cause of each change matters.

Snapshot

State at a point in time

A structured feature record for one observation — a patient visit, a genome with its collection date, a language stage. Typed by data source. The ground-truth observational layer; nothing inferred.

Transition

A change, plus a hypothesis about its cause

The change between two snapshots, carrying a probability distribution over competing mechanisms — a soft belief state that updates as evidence arrives. Disagreement between independent passes is kept as variance, not averaged away.

Centroid

Multi-resolution aggregate

Visit → year → decade → stage. Stores full distributions and spread, not just means. High spread is a triage signal: it marks the windows that deserve a closer look before a single raw snapshot is opened.

A snapshot-only system is descriptive. Snapshots plus transitions is a causal inference system — because a transition is a hypothesised event with evidence and uncertainty attached, not a diff.

The grammar

Rules that compose evidence, not a weight matrix.

A weight matrix says “this feature contributes 0.4 to that cause.” A grammar says how evidence has to combine before a cause can be derived at all — conjunction, alternation, and exclusion that additive weights flatten.

fig. 1 — one production rule. The NOT arm is exclusionary logic a weight matrix cannot represent cleanly.

The grammar also constrains what can be said. If no rule connects the observed evidence to a cause, that attribution cannot be derived — an illegal jump becomes a parse failure, not a low-probability output. That is a structural admissibility check, not a claim that the mechanism is false, and it is only as good as the rules. Getting the production rules right needs domain-expert grounding, and building them out is staged: admissibility first (legal / illegal / incomplete), composition later, quantitative rule semantics only if the payoff shows up.

The machine

Agents interpret evidence. They are not the inference engine.

A recurring failure mode in multi-agent systems is letting a language model quietly implement probability theory. Here the reasoning and the arithmetic are split.

fig. 2 — the inference path for one transition.
Agentsjudge — is this evidence strong or weak support, and for which hypothesis
Grammarconstrains — is this derivation structurally legal
Updatercomputes — turns ordinal judgements into a belief state by a published, versioned rule
Databaseremembers — every belief change references its evidence and its grammar version
Meta-agentinvestigates — routes disagreement, finds cross-instance patterns, asks for the next observation

Specialist agents are meant to be persistent, serializable domain experts: the model supplies reasoning, a database supplies the accumulated knowledge — validated patterns, open hypotheses, past judgements, calibration history. A new session resumes with everything that agent has learned about its scope, rather than starting cold.

A worked example

The 1977 Galápagos finch drought, one cycle end to end.

The most documented natural-selection event in the literature: a drought crashed the medium ground finch population from ~1,240 to ~180, and the survivors had measurably deeper beaks. Here is that transition moving from raw rows to a stored, queryable belief.

Beat 1 — two snapshots define the transition

State before, state after

// snapshot A — 1976, pre-drought
{
  "population":  { "size": 1240, "survival_rate": 0.84 },
  "morphology":  { "mean_beak_depth_mm": 9.42 },
  "environment": { "annual_rainfall_mm": 130,
                   "seed_hardness_index": 0.40,
                   "seed_abundance_index": 0.74 }
}
// snapshot B — 1977, drought survivors
{
  "population":  { "size": 180, "survival_rate": 0.15 },
  "morphology":  { "mean_beak_depth_mm": 9.84 },
  "environment": { "annual_rainfall_mm": 24,
                   "seed_hardness_index": 0.91,
                   "seed_abundance_index": 0.18 }
}

The feature extractor computes the deltas: beak depth +0.42 mm, survival 0.15, rainfall −81%.

Beat 2 — predicates fire, producing evidence atoms

Named facts, not column values

A predicate registry maps environment.annual_rainfall_mm < 40 to severe_drought, and so on. Rules only ever see the atoms:

drought severe_drought seed_hardness_high seed_scarcity population_bottleneck beak_depth_increased el_nino competitor_present immigration_detected

If a rule references a predicate the registry doesn't define, it fails at load time — not silently at inference time.

Beat 3 — the grammar runs

Horn clauses over the atoms

# what a domain expert authors (YAML)
- id: drought_selects_large_beak
  conclusion: directional_selection_larger_beak
  probability: 0.88
  all_of: [ drought, seed_hardness_high,
            seed_scarcity, population_bottleneck ]

- id: severe_drought_amplifies
  conclusion: directional_selection_larger_beak
  probability: 0.92
  all_of: [ severe_drought, seed_hardness_high,
            population_bottleneck ]
selection‑primary v1.0confidence 0.94
directional selection · larger beak.97

Both rules' bodies are satisfied; the engine combines them. The el_niño and character-displacement rules have false atoms in their bodies and don't fire. Every fired and un-fired rule is recorded in rule_trace.

Beat 4 — perturb the theory, keep both versions

Remove one rule; see what the posterior does

Create selection-primary v2.0 by deleting drought_selects_large_beak. Re-run the same transition. The new score lands in a new row beside the old one — neither overwrites the other.

v1.0 — full grammarconfidence 0.94
directional selection.97
v2.0 — drought rule removedconfidence 0.41
directional selection.52
stabilizing / relaxed.42

One overlapping rule still fires, so the conclusion bends rather than collapses — but confidence drops from 0.94 to 0.41. This is structural sensitivity analysis: not “what if the weight were 0.80” but “what if this causal pathway weren't in the theory at all.” The v1-vs-v2 comparison, across every transition in the dataset, is now one query: 

SELECT v1.cause_distribution->>'directional_selection_larger_beak' AS v1_p,
       v2.cause_distribution->>'directional_selection_larger_beak' AS v2_p,
       v1.confidence - v2.confidence AS confidence_drop
FROM transition_inferences v1
JOIN transition_inferences v2 USING (transition_id)
WHERE v1.grammar_version = '1.0' AND v2.grammar_version = '2.0';
Where it applies

Same machinery, different production rules.

Snapshots, transitions and centroids fit any longitudinal system with competing causal explanations. Only the grammar is domain-specific.

Historical linguistics

transition  ·  Late Latin → Old French  ·  5th–9th c.

Was a sound change inherited, borrowed, or driven from below by a substrate population? The three answers imply completely different histories, and a tree — which only encodes descent — can't hold the question. A transition object can: { contact: 0.35, drift: 0.33, substrate: 0.32 } is a near-even split that flags exactly where the comparative method is doing the most guessing.

The proof-of-concept targets the Germanic branch with ASJP data, using Grimm's Law and Verner's Law as rule-level ground truth — Verner's environmental conditioning is a clean test of whether a grammar can tell a compositional explanation from a coincidental one.

Viral & cancer genomics

transition  ·  two genome snapshots weeks apart

Model-Based Hypothesis Testing already computes posteriors over “within-host vs. immune selection” for viral evolution — and a 2025 review calls the approach “powerful yet underutilised.” It runs as a separate step after phylogenetic inference, produces one run's posterior rather than a maintained belief, and isn't queryable at scale.

Recombination — common in coronaviruses and influenza — is a network event, not a tree branch. In an AND/OR grammar it is simply an AND-edge between two lineages. The cross-instance meta-agent answers a question researchers currently do by hand: which transition type is converging across independent lineages in the same time window.

The speculative payoff: if the rule structure for “substrate influence” in linguistics turns out to be formally identical to “host immune landscape pressure” in virology, that similarity is itself a finding — a hint at domain-independent patterns in how structured systems change under external constraint. The architecture at least makes the question askable.

Status

Written, not yet run.

This is a concept with a proof-of-concept scaffold, not a working system. The honest state:

  • Built

    A six-service Docker Compose scaffold — Postgres canonical store, Redis coordination, a ProbLog inference service, scalable specialist agents, a meta-agent, a REST API. Grammar authoring in YAML compiling to ProbLog.

  • Now

    Phase 0 — a tracer bullet. One transition, two deliberately conflicting hardcoded rules, run end to end, with one derivation tree generated and stored. Not “the containers start” — one real artefact you can look at.

  • Before Phase 1

    A falsification test. On 30–50 transitions with expert-known outcomes, compare (A) one strong model, (B) model + evidence atoms + an admissibility grammar, (C) B + ordinal specialist judgements + the deterministic updater. If B and C perform the same, the multi-agent layer isn't earning its cost — and that's a useful result.

  • Open

    The grammar production rules don't exist yet and need domain-expert grounding. No calibration strategy is defined. The adaptive temporal-window algorithm is unspecified.

On the name. The project started as “Expert Swarm,” which oversold the multi-agent part. Transition-Centered Inference is the current working name for the substrate — the persistent transition / evidence / grammar / belief record. The agent swarm is one implementation on top of it, and a pluggable one.
